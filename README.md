# ก๋วยเตี๋ยวไก่มะระ — ร้านค้า POS

เว็บสำหรับคนขายบันทึกยอดหน้าร้านบนมือถือ ไม่รวมหน้าลูกค้าสั่งอาหาร

## ใช้งาน
1. เปิดเว็บและเข้าสู่ระบบด้วย ChatGPT บัญชีเจ้าของเว็บ
2. ครั้งแรกกด **เพิ่มเมนูของร้าน** เพื่อใช้ราคาในภาพ: ก๋วยเตี๋ยวหมูน้ำใส/ต้มยำ และก๋วยเตี๋ยวไก่/ไก่น้ำต้มยำ ธรรมดา 35 บาท พิเศษ 45 บาท; เกาเหลาไก่/หมู 50 บาท
3. เลือกเมนู เส้น และหมายเหตุ แล้วเพิ่มลงบิล
4. กดรับชำระเงิน เลือกเงินสดหรือเงินโอน สำหรับเงินสดระบุยอดรับ ระบบคำนวณเงินทอนให้ สำหรับเงินโอนตรวจเงินเข้าด้วยตัวเอง
5. กด **ยืนยันว่าจ่ายแล้ว** เพียงครั้งเดียว หากการเชื่อมต่อผิดพลาดให้ตรวจสอบและบันทึกบิลเดิมอีกครั้ง
6. ดูหรือยกเลิกบิลในหน้าบิล โดยระบุเหตุผล หน้ายอดขายไม่นับบิลที่ยกเลิก
7. ส่งออก JSON จากหน้ายอดขายเป็นประจำ ไฟล์นี้มีข้อมูลทั้งหมด ระบบยังไม่มีหน้ากู้คืนจากไฟล์; ผู้พัฒนาสามารถนำกลับเข้าฐานข้อมูลได้

ข้อมูลจริงอยู่บน Cloudflare D1 แยกตามบัญชีผู้ใช้ ไม่ได้เก็บเฉพาะในมือถือ ต้องมีอินเทอร์เน็ต ไม่มีระบบตรวจสอบเงินโอนอัตโนมัติ ไม่มีระบบสต็อก ไม่มีพิมพ์ใบเสร็จภาษี บิลร่างในแท็บเก็บใน sessionStorage เพื่อช่วยกู้เมื่อรีเฟรช; การปิดแท็บหรือล้างข้อมูลเว็บอาจลบร่างได้ บิลที่บันทึกแล้วอยู่ในฐานข้อมูล

## เทคโนโลยี
TypeScript, React 19, Vinext (Next.js App Router API), Vite, Tailwind CSS, Radix/Shadcn, Cloudflare Workers + D1, Drizzle migrations, Zod.

## พัฒนาต่อ
ต้องใช้ Node.js 22.13 ขึ้นไป (ทดสอบบน Node 24) และ npm

```sh
npm ci
npm run build
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_black_tinkerer.sql
npm run dev
```

ใช้ URL ที่ dev server แสดง เช่น http://localhost:5173/ และกดเข้าสู่ระบบเพื่อใช้บัญชีจำลองเฉพาะเครื่อง ข้อมูลทดสอบแยกจากออนไลน์

```sh
npx tsc --noEmit
node tests/integration.mjs
```

Integration test ใช้ dev server ที่ localhost:5173 และเมนูที่เริ่มต้นแล้ว จะสร้างข้อมูลทดสอบในฐานข้อมูล local เท่านั้น แล้วปิดสินค้า/ยกเลิกบิลทดสอบ เก็บบิลเหล่านี้ไว้ตรวจสอบ

## โครงสร้าง
- `app/pos.tsx`: หน้าร้าน บิล รายงาน เมนู
- `app/api/pos/route.ts`: API ตรวจข้อมูล/สิทธิ์ และบันทึกธุรกรรม
- `lib/pos.ts`: ชนิดข้อมูล เงิน และเมนูตามภาพ
- `db/schema.ts`, `drizzle/`: schema และ migration
- `.openai/hosting.json`: Sites ID และ logical D1 binding

เผยแพร่ผ่าน Sites โดยเข้าถึงแบบเจ้าของคนเดียว โค้ด auth อาศัย identity headers ที่แพลตฟอร์มตรวจให้ หากย้ายไปโฮสต์เองต้องเพิ่ม trusted authentication gateway ก่อนใช้งาน ห้ามเปิด Worker โดยตรงแล้วเชื่อ header จากอินเทอร์เน็ต

## การตรวจสอบ
- ตรวจชนิด TypeScript และ production build
- API: ไม่ได้เข้าสู่ระบบ, origin ไม่ถูกต้อง, เงินไม่พอ, จำนวนติดลบ, ราคาไม่ตรง, กดพร้อมกันสองครั้ง, ราคาเดิมในบิล, ยกเลิกบิล, เงินโอน, เมนูปิดขาย
- UI: เลือกเส้น เพิ่มลงบิล รับเงินสดและเงินทอน ที่ขนาดจอมือถือ 390×844

## ขอบเขตปัจจุบัน
เหมาะกับร้านเดียวและบัญชีเจ้าของเดียว โหลดประวัติบิลทั้งหมดเมื่อเปิดหน้า ยังไม่มี pagination สำหรับประวัติขนาดใหญ่มาก ไม่มีการรับประกัน uptime หรือ automated backup จากโค้ดนี้ ตรวจแพ็กเกจโฮสติ้งก่อนพึ่งพาการสำรองของผู้ให้บริการ
